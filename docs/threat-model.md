# blook-kchannel threat model

Scope: a user-mode loader (`kc_client`) and a kernel driver that may be loaded
by a manual mapper (no `DriverObject`, no image entry in
`PsLoadedModuleList`) communicating over one anonymous shared-memory section.

## 1. Adversary

The adversary is a user-mode anti-cheat / EDR equivalent that can:

- enumerate device objects, symbolic links, named objects, services, registry
  keys, loaded modules and handles;
- scan its own process memory (and, if it has arbitrary kernel read, anything);
- observe timing and CPU usage;
- send malformed input to anything the loader exposes.

The adversary is assumed **not** to already have arbitrary kernel
read/write on the machine (that would subsume the whole design).

## 2. Assets

1. **Session key** - 32 random bytes, generated by the loader. Only travels
   through the `kc_bootstrap` descriptor; never written to the shared region.
2. **Control page / rings** - user-owned memory. Never trusted by the kernel.
3. **Stealth invariants** - no device object, symbolic link, registry key,
   named object, notify routine, SSDT hook, image-load notify or exported
   symbol in the production path.

## 3. Guarantees

| Threat | Mitigation |
|---|---|
| Passive read of the shared section | Payloads are encrypted (ChaCha20 or AES-128-CTR); headers are authenticated. The region contains no key material. |
| Forged/edited frames | HMAC-SHA256 over header `[0,0x30)` + ciphertext, truncated tag compared in constant time; any mismatch is `KC_ERR_AUTH`. |
| Replay of a captured record | Strictly increasing per-direction `seq`; duplicates are rejected. Nonces are derived from `prefix` + `seq`, so seq reuse would reuse keystream - therefore seq is monotonic and the ChaCha20 seq ceiling is enforced. |
| Session hijack / wrong key | Kernel publishes `session_tag = HMAC(key, label||salt||attach_id||pid)`; a loader that cannot recompute it is not talking to a kernel with its key. `HELLO` then re-checks `attach_id`/pid. |
| Stale peer, PID reuse | `attach_id` is per attach and checked in the handshake; the user heartbeat + watchdog detects a dead loader within `watchdog_ms` (default 5 s). |
| Second client / cross-connect | One kernel object accepts one peer; a second bootstrap yields `KC_ERR_ALREADY` and the driver's `g_live_kernel` slot is cleared only after teardown. |
| Malformed/truncated/tampered input causing a bugcheck | All geometry, lengths, alignment, seq and state are validated; every region access goes through bounds-checked `MemOps`; exceptions are contained (`MmProbeAndLockPages` in SEH; COPY mode uses `MmCopyVirtualMemory`). Host fuzz tests cover corrupt heads/tails/geometry/records. |
| Detection via device/registry traces | Production path creates none of them. The test-signed path (`KCHANNEL_TESTING` build of `kchannel_test.sys`) does, by design, and the e2e `trace-scan` proves the mapped path has no such traces. |
| Kernel CNG dependency (unavailable in mapped images) | SHA-256, HMAC, ChaCha20 and AES-CTR are implemented in-tree; the kernel library imports only documented ntoskrnl/WDM entry points. |
| Loader death leaking kernel memory | MAPPED: the MDL/unlock/mapping is torn down by `kc_kernel_destroy` (peer-gone path or unload). COPY: no resident mapping at all. |

## 4. Non-goals / residual risks

- **Any user-mode process running as the loader's user** can read the
  session key from the loader's memory. The transport defends against a
  different process / same-user forensic scanner only insofar as the key is
  not in the shared region.
- **A malicious loader is outside the model**: it owns the region and can only
  corrupt its own session. The kernel still must not crash (tested), and does
  not.
- **Watchdog latency**: peer death is detected by heartbeat timeout, not by a
  process notify (forbidden by the stealth invariants). Default 5 s; a driver
  can lower `watchdog_ms`.
- **No forward secrecy / no rekeying** in ABI 1.0. A new attach gets a new key.
- **Heartbeat is not a cryptographic liveness proof.** An attacker with write
  access to the region can keep a dead session looking alive for up to
  `watchdog_ms` - they still cannot forge traffic without the key.
- **Side channels**: latency/CPU usage can reveal that a driver is polling.
  The adaptive backoff keeps idle cost near 0.1 % of one core and the stop
  bound at 50 ms.
- **COPY mode** copies through `MmCopyVirtualMemory`, which attaches to the
  loader process per transfer; a terminating process returns
  `STATUS_PROCESS_IS_TERMINATING` (mapped to `KC_ERR_PEER_GONE`) instead of
  bugchecking.
- **Test-only IOCTL bootstrap** (service load) exists only in
  `KCHANNEL_TESTING` builds of the test driver; the library itself does not
  create devices in any build.

## 5. Verification

- Host fuzz/tamper suite (41 tests) in `tests/unit`: crypto RFC vectors,
  ring corruption, framing tamper/truncation, malformed-record fuzz, replay,
  hostile control-page mutation, timeout/backpressure.
- VM e2e (`tests/e2e`): wrong key -> `KC_ERR_AUTH`, duplicate attach ->
  `KC_ERR_ALREADY`, loader kill -> peer-gone cleanup + recovery, unload ->
  no device/service-key residue, mapped driver -> no device/registry/module
  traces, deliberate fault -> host-side BSOD detection (proves the harness can
  see a real crash).
- Evidence committed under `docs/evidence/`.
