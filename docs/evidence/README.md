# Evidence

Every directory here is produced by a real run, never hand-written.

- `YYYYMMDD-ci/` - GitHub Actions run evidence: `result.json` (run URL, job
  conclusions, commit) and `host-unit.txt` (`xmake run kchannel-unit-tests`).
- `YYYYMMDD-vm-e2e/` - bvmenv VM evidence produced by
  `tests/e2e/run-e2e.ps1`:
  - `result.json` - summary: VM name, commit, bvmenv `outcome` for the main
    matrix and the deliberate-BSOD harness, evidence directory.
  - `metrics.json` - machine-readable performance objects extracted from the
    guest stdout (latency median/p95/p99 for 64 B / 4 KiB, mapped and copy
    transports, worker-thread CPU %, `kc_kernel_stop` latency, 100k soak,
    mapped trace scan). `tests/e2e/render-performance.ps1` renders them into
    the PERF block of `docs/performance.md`.
  - `main/<run_id>/` and `crash/<run_id>/` - raw `bvmenv.e2e.v1` artifacts:
    `result.json`, `stdout.txt`, `stderr.txt`, `state.json`,
    `state-before.json`, `screen.png` (host-captured frame).
  - `blook-kchannel-test.cer` - public test certificate (no private key).
  - `signed/`, `bundle/`, `crash-bundle/` are regenerated by the runner and
    intentionally not committed (see `.gitignore`); they contain the signed
    `.sys` files used for the run.

A VM evidence directory only exists when a real bvmenv run produced it; if the
lab base image is unavailable the runner refuses to run (host safety) and no
directory is created.
